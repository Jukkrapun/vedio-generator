# แผน: ภาพเคลื่อนไหวจริงด้วย Wan 2.1 / 2.2 บน vast.ai — ร่าง 2026-11-23

สถานะ: **ข้อเสนอ รอผู้ใช้ตัดสินใจ** · ยังไม่ได้เช่าเครื่อง ยังไม่เสียเงิน

## เป้าหมาย

เปลี่ยนบางฉากในคลิปโหมด `image` จากภาพนิ่ง (ตอนนี้เป็น parallax) ให้**ของในภาพขยับจริง** เช่น ควันจากแก้ว ฝนบนกระจก ผ้าม่านไหว มือเลื่อนโทรศัพท์ ไฟเมืองกะพริบ
โดยใช้รูปจาก Codex ที่มีอยู่แล้วเป็นเฟรมแรก (image-to-video) จะได้ไม่ต้องทำรูปใหม่ และหน้าตา/โทนภาพตรงกับของเดิม

ไม่ใช่เป้าหมาย: ให้ใบเตยพูด (นั่นคือ lip-sync POC ที่พักไว้ — ดู `docs/lipsync-poc/SUMMARY.md`)

## ตัวเลือกโมเดล (โอเพนซอร์ส Apache-2.0 ใช้เชิงพาณิชย์ได้)

| โมเดล | ขนาด | ความละเอียด | GPU ที่ต้องใช้ | หมายเหตุ |
|---|---|---|---|---|
| **Wan 2.2 TI2V-5B** | 5B | 720p (1280×704 / 704×1280), 24fps | 24GB (RTX 4090 / 3090 / A5000) | ถูกและเร็วที่สุด ตัวเต็งสำหรับใช้งานจริง |
| **Wan 2.2 I2V-A14B** | 14B ×2 (MoE) | 480p / 720p | 80GB (A100/H100) หรือ 24–48GB + offload (ช้า) | คุณภาพการเคลื่อนไหวดีที่สุด แพงกว่า |
| Wan 2.1 I2V-14B | 14B | 480p / 720p | 40–80GB | รุ่นก่อน ไม่มีเหตุผลเลือกแทน 2.2 ยกเว้นจะใช้ LoRA ที่มีเฉพาะ 2.1 |
| Wan 2.1 T2V-1.3B | 1.3B | 480p | 8GB | text-to-video เท่านั้น ใช้รูปเราไม่ได้ → ไม่เหมาะ |

ตัวช่วยความเร็ว: LoRA **lightx2v** (distill เหลือ 4–8 steps แทน ~40) ใช้ได้กับ 14B — ลดเวลาหลายเท่า (ใช้แล้วใน InfiniteTalk POC)
คลิปต่อรอบ ~5 วินาที (81 เฟรม @16fps สำหรับ 14B, 121 เฟรม @24fps สำหรับ 5B)

**ข้อเสนอ:** ทดสอบ 2 ตัวใน POC → **TI2V-5B บน 4090** เทียบกับ **I2V-A14B + lightx2v บน A100** แล้วเลือกตัวเดียว

## ประมาณเวลา/ค่าใช้จ่าย (ประมาณการ — ต้องวัดจริงใน POC)

บทเรียนจาก lip-sync POC: บิลจริงของ vast **สูงกว่าที่สคริปต์ประเมิน** และค่า setup (เช่า+บูต+โหลดโมเดล) กินเวลาพอๆ กับงานจริง → ต้องรันเป็น batch

| | TI2V-5B / 4090 (~$0.35–0.5/ชม.) | A14B + lightx2v / A100 80GB (~$1.0–1.4/ชม.) |
|---|---|---|
| setup ต่อรอบ (เช่า+บูต+โหลดโมเดล) | ~5–10 นาที | ~8–12 นาที |
| ต่อคลิป 5 วิ | ~3–9 นาที | ~3–6 นาที |
| batch 10 ฉาก (≈ 3–5 ตอน) | ~1–1.5 ชม. ≈ **$0.4–0.8** | ~1 ชม. ≈ **$1–1.5** |

เทียบ: fal.ai แบบเสียเงินต่อคลิป ~$0.2–0.5 ต่อ 5 วิ → 10 ฉาก ≈ $2–5 (ไม่ต้องดูแลเครื่อง)

## สถาปัตยกรรม (ใช้ pattern เดียวกับ `musetalk_vast.py` / `infinitetalk_vast.py`)

1. **episode.json** — ต่อ segment:
   ```json
   {"image": "images/02-insight.png", "visual": "motion",
    "motion_prompt": "steam slowly rising from the mug, rain drops sliding down the window, camera still"}
   ```
   segment ที่ไม่ใส่ `"visual": "motion"` ยังใช้ parallax เหมือนเดิม
2. **`tools/motion_vast.py`** — รับหลาย episode → รวมทุกฉากที่ขาดคลิป → เช่าเครื่องเดียว → ติดตั้ง Wan + โหลดโมเดล (ครั้งเดียว) → สร้างทีละฉาก → ดาวน์โหลดเป็น `video/<image-stem>.motion.mp4` → **ลบเครื่องเสมอ** (รวมตอน error) เก็บ id ใน `.vast-instance.json`, มี `--offers`, `--cleanup`, `--dry-run` (บอกราคา/เวลาโดยประมาณก่อนเช่า)
3. **cache** — `video/<stem>.motion.json` เก็บ hash ของรูป + prompt + model + seed; ไม่เปลี่ยน = ไม่สร้างซ้ำ (เหมือน TTS cache)
4. **`render_reel.py`** — segment `motion`: ใช้คลิปนั้น ปรับให้ยาวเท่าเสียง (สั้นกว่า → ชะลอเล็กน้อย/ต่อด้วย parallax ของเฟรมสุดท้าย, ยาวกว่า → ตัด) + grade/fade เดิม · ไม่มีคลิป → ใช้ parallax พร้อมคำเตือน (ระบบไม่ล้ม)
5. **`produce.py`** — ขั้นตอนใหม่หลัง images: `motion_vast` แบบ batch (ข้ามถ้าไม่มี segment motion) · ต้องถามยืนยันก่อนเช่าจริงเพราะเสียเงิน
6. **เว็บ ops** — stage `images` แสดงคลิป motion ให้ดู/อนุมัติ และปุ่ม "สร้างใหม่ฉากนี้" (เปลี่ยน seed/prompt) · รันบน host worker เท่านั้น (Docker worker ไม่มี vastai/ssh key — เหมือน MuseTalk)
7. **Docker image สำเร็จรูป** — ตัดสินใจหลัง POC: 5B (~20–30GB รวมโมเดล) push ขึ้น Docker Hub ได้ → บูตเร็ว · 14B ใหญ่เกิน → ติดตั้ง + ดึงโมเดลจาก Hugging Face บนเครื่อง (แบบ InfiniteTalk)

## กติกาการใช้ (คุมงบ + คุมคุณภาพ)

- **1–2 ฉาก motion ต่อคลิป** (ปกติ = hook ฉากแรก) ที่เหลือ parallax
- prompt แบบ "เคลื่อนไหวเล็กน้อย กล้องนิ่ง" — เข้ากับโทนดึกๆ และลดโอกาสภาพเพี้ยน
- เลี่ยงฉากเห็นหน้าคนชัดๆ (Wan มักทำหน้าเปลี่ยน) — ภาพของช่องส่วนใหญ่เป็นมุมหลัง/มือ/สิ่งของอยู่แล้ว ซึ่งเหมาะ
- เพิ่มกติกานี้ใน `PROMPTS.md` และ `series.md` ของแต่ละซีรีส์หลังผ่าน POC

## สิ่งที่ต้องการให้ผู้ใช้ตัดสินใจ

1. เริ่มเฟส 0–1 (POC) ไหม และงบ POC เท่าไร (เสนอ ~$5 เติมครั้งเดียว ใช้จริง ~$1–2)
2. ทดสอบทั้ง 2 โมเดล หรือเริ่มที่ TI2V-5B (ถูกกว่า) อย่างเดียว
3. รูปทดสอบ: ใช้ 4 รูปที่เสนอ หรือมีฉากที่อยากเห็นขยับเป็นพิเศษ
